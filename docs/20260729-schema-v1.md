## 1. 记录表（唯一表）

本系统只有一张记录表，所有数据（原始记录、复盘、账单、体征）都在同一张表里，靠 tag 区分。

### 1.1 字段定义

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | UUID（v7） | PK，NOT NULL | 唯一 ID。v7 是 time-ordered（毫秒时间戳前缀 + 随机尾），单调递增，同时充当主键与"最新写入"判据 |
| `happened_at` | `TIMESTAMP WITH TIME ZONE` | 可空 | 事件实际发生时间。模糊时间塌缩为精确值后存入；可空（如用户说了一句话但没提及时间） |
| `value_numeric` | `NUMERIC` | 可空 | 数值型记录的值（体重 70.5、消费 15、体脂率 22.3…）。text 型记录留空。不可与 value_text 同时为空 |
| `value_text` | `TEXT` | 可空 | 文本型记录的内容（用户原始发言、复盘文字…）。numeric 型记录留空。不可与 value_numeric 同时为空 |
| `tags` | `TEXT` | NOT NULL | JSON 字符串数组，如 `["工作","学习"]`。tag 值内部**不能含双引号**（§2.5）。至少一个 tag |
| `context` | `TEXT` | 可空 | 对话上下文：AI 的分析、提问、讨论背景等。在 bare 回复场景中是必填项（§7.12） |
| `raw_time_text` | `TEXT` | 可空 | 原文中的自然语言时间（如"今天下午"），原样保留。用于回溯/审计 |

> 共 7 个字段。`recorded_at` 由 `id`（UUIDv7）兼任；`happened_until` 已砍，所有记录都是点事件。

### 1.2 字段语义契约

- `happened_at` 可能是从模糊时间塌缩而来的精确时间点，并非都是真实测得的精确值。该契约写在接口文档/UI 说明里，不进逐条数据。
- `value_text` 存的是用户原始发言（§1.9），与衍生字段（`happened_at` / `value_numeric`）冗余并存，不能"抽走就删"。
- `context` 存的是对话上下文，同样逐字保真，不重新生成（§7.12）。
- 数值型必须有独立的 `value_numeric`，不能与文本合并（S7：保证机器可统计性）。

## 2. 设计原则

### 2.1 append-only（对 AI 接口）

- AI 只能 POST 新记录，不提供 UPDATE/DELETE 接口；
- 错误处理：
  - 单条事实层小错 → 新增勘误记录（自然语言说明上一条错误）
  - 影响统计的错误（如 tag 重复） → 用户直接改库
- 人与 AI 权限不对称：append-only 是 AI 接口约束，不是数据库硬约束。

### 2.2 数值类口误：覆盖 + 反向

**体征类（体重/体脂/身体成分）—— 覆盖**：
- 口误后再记一条正确值，不改原记录；
- 取值规则：同一天有多条记录时，先按 `happened_at` 取当天，再按 `id`（UUIDv7）取最大值（最新写入）作为当天代表值。

**账单类 —— 反向账单**：
- 账单 20 说成 30 → 记一条 -30 的反向账单 + 一条 +20 的正确账单；
- 机械 SUM 自动平掉，不需要特殊字段。

### 2.3 tag 存储

- 以 TEXT 存 JSON 字符串（如 `["工作","学习","source:device"]`），不用 PG 特有类型；
- tag 值不能含双引号——这样精确搜索 `LIKE '%"tag名"%'` 可用双引号作边界，不会误匹配子串；
- 不建独立 tag 表，不引入外键；
- tag 数量保持克制，细粒度词靠模糊搜索（`q` 参数）找回。

### 2.4 客观/主观分离

- 强相关的主观感受（如"又胖了想减肥"随体重、"价格真贵"随消费）→ 同行存入数值接口的 `value_text`；
- 独立判断/联想（如"可乐配鸡腿饭真好吃"是对两次消费的组合评价）→ 单独走 `/log/text/record`。

## 3. 三大类录入接口

### 3.1 数值类：`POST /log/numeric/{kind}`

URL 路径承载语义，AI 一看就知道在记什么。

| 接口 | 说明 |
| --- | --- |
| `/log/numeric/bill` | 记账（金额 + 消费类别 tag + 时间） |
| `/log/numeric/weight` | 记体重 |
| `/log/numeric/body_composition` | 体脂秤批量录入（一次调用，后端内部拆成 N 条入库） |
| `/log/numeric/{...}` | 其他数值类各自单独接口（如血压） |

**批量录入模式**（体脂秤场景）：
- 接口 schema 写死各项（因用户一直在同一台体脂秤测量，各项数目固定）；
- AI 调用一次，后端内部拆成 N 条记录入库；
- AI 永远"一次调用一件事"，不暴露拆分复杂度。

### 3.2 文本类：`POST /log/text/{kind}`

| 接口 | 说明 |
| --- | --- |
| `/log/text/record` | 通用文本记录（行为、感受、思考…），可传任意 tags |
| `/log/text/review/daily` | 日复盘 |
| `/log/text/review/weekly` | 周复盘 |
| `/log/text/review/monthly` | 月复盘 |
| `/log/text/review/{周期}` | 其他周期复盘 |

### 3.3 通用 payload 规范

所有接口的 payload 共同字段：

```json
{
  "happened_at": "2026-07-29T19:00:00+08:00",
  "value_numeric": null,
  "value_text": "今天背了50个单词",
  "tags": ["学习", "单词"],
  "context": null,
  "raw_time_text": "今天下午"
}
```

- `happened_at`：ISO 8601 带时区字符串。模糊时间由 AI 塌缩为精确值。
- `tags`：JSON 数组，至少一个 tag。
- `value_numeric` / `value_text`：至少填一个，不可同时为空。
- `context`：可空。bare 回复场景必填。

### 3.4 鉴权

- token 通过环境变量注入（`DIGITAL_TWIN_TOKEN`），不硬编码；
- AI 不直接发 HTTP，通过 CLI 工具包装——AI 只给 JSON payload，CLI 内部加 token；
- Web 前端访问也需要携带 token。

## 4. 查询接口

### 4.1 通用查询（所有类型通用）

```
GET /query?from=...&to=...&tag=...&tag=...&q=...
```

| 参数 | 说明 |
| --- | --- |
| `from` / `to` | ISO 8601 带时区字符串，对 `happened_at` 过滤，半开区间 `[from, to)`，任一端可省略 |
| `tag` | 多 tag 传多次，仅 AND 语义（命中记录需同时带所有传入 tag）。不提供 OR——AI 想要并集自己多次调用再合并 |
| `q` | 模糊搜索，对 `value_text` / `context` / `tags` 做 `LIKE '%关键词%'` 匹配 |

**不支持的过滤**：
- 不按 `value_numeric` 数值范围过滤（AI 拉出来后自己筛）
- 不提供通用聚合（账单除外）

### 4.2 账单汇总查询（§5.7 的唯一例外）

```
GET /query/bill/summary?from=...&to=...
```

- 强制必须传时间区间，不做终身总账单；
- 返回多级 JSON：

```json
{
  "income": 15000,
  "expense": 8500,
  "net": 6500,
  "by_category": {
    "收入": { "工资": 12000, "投资收益": 3000 },
    "支出": { "饮食": 3000, "交通": 500, "娱乐": 800 }
  }
}
```

## 6. 复盘体系

### 6.1 层层递进

| 复盘周期 | 触发方式 | AI 读什么 |
| --- | --- | --- |
| 日复盘 | 用户主动（当晚或次日晨） | 当日全部明细记录 |
| 周复盘 | 周末 | 本周全部明细 |
| 月复盘 | 月末或下月初 | 本月明细，或本月所有周复盘 |
| 季/半年/年复盘 | 周期末 | 基于短周期复盘的记录再做"复盘的复盘"，需要时才回拉明细 |

### 6.2 复盘记录的本质

- 就是一条带 `review:*` tag 的普通记录，结构上与其他记录无区别；
- `happened_at` 是复盘发生的时刻（如周末晚上 7 点）；
- 内容混合：历史回顾 + 对历史的评价 + 当下状态心情；
- 跨期复盘检索（如找 7 月复盘）：AI 用 `happened_at` 划大致时间范围 + `tag=review:monthly` 筛选 + 读 `value_text` 确认。

### 6.3 对话记录规则

- 每一次用户发言都是一条记录，禁止多轮讨论攒成一条总结；
- 完整语句 → `value_text` 原话保真，`context` 可空；
- bare 回复（如"你说的对"） → `value_text` 原话保真，`context` 必填 AI 的完整发言上下文。
